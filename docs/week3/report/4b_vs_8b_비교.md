# Qwen3-4B-Instruct vs Qwen3-8B — 신규 영문 프롬프트(v2) 기준 비교 보고서

3주차 보고서 §5(4B vs 8B 비교)에서 사용한 4B 모델은 **하이브리드(thinking) 변종 `qwen3:4b`** 였고, `/no_think`·`think=False` 디렉티브를 무시하여 reasoning 출력만 뱉다 잘리는 결함이 있었다. 이 결함을 인지한 뒤 **Instruct 전용 변종 `qwen3:4b-instruct`** 로 교체했고, 이어서 영문 프롬프트를 v2(간소화·구조화 출력 형식)로 갱신했다. 본 보고서는 이 두 변경 후의 4B-Instruct와 8B를 같은 v2 프롬프트로 재측정한 결과를 정리한다.

| 프롬프트 | `prompts.py` SYSTEM_PROMPT_EN v2 — 영문 지시·**한국어 출력**·구조화 접두사(`카테고리:` / `보조 카테고리:` / `신규 카테고리:` / `분류 불가:`) |

## 3. `기타`(n=13) 처리 비교

`기타`는 [CATEGORY LIST]에 없는 라벨이므로 모델은 `<unclassifiable>` / `<new_category>` / 기존 LABEL 흡수 셋 중 하나로 분기한다.

| 처리 결과 | Qwen3-8B | Qwen3-4B-Instruct |
|---|---:|---:|
| 기존 LABEL로 흡수 | 11 (84.6%) — 원산지증명서 9, 상업송장 2 | 6 (46.2%) — 원산지증명서 6 |
| `<unclassifiable>` (분류 불가) | 0 (0.0%) | **4 (30.8%)** |
| `<new_category>` (신규 제안) | 2 (15.4%) — 품질증명서 | 3 (23.1%) — 품질증명서 |

- **8B**: `분류 불가`를 한 번도 사용하지 않고 84.6%를 기존 LABEL로 강제 흡수. 4-class 정확도는 완벽하지만, `기타` 거부율은 **0%** 다.
- **4B-Instruct**: `분류 불가`를 30.8% 사용 — **거부 정책이 더 보수적**. 흡수 비율도 절반 수준.

→ 4-class 정확도만 보면 8B 압승이지만, **운영 시 "확실치 않으면 사람이 검토"** 가 필요한 정책에서는 4B-Instruct의 거부 분기가 오히려 유용할 수 있다.

## 4. 신규 카테고리 제안

| 모델 | 제안 횟수 | 종 수 | 제안된 명명 |
|---|---:|---:|---|
| Qwen3-8B | 2 | 1 | `품질증명서` ×2 |
| Qwen3-4B-Instruct | 3 | 1 | `품질증명서` ×3 |

두 모델 모두 동일한 명명(`품질증명서`)을 사용하고 도메인 적합 + 명명 규칙(2~10자, 한국어, 비-catch-all)을 만족한다. 다만 8B가 v1 프롬프트에서 보였던 풍부한 다양성(`Certificate of Origin`·`Marine Cargo Insurance Policy` 등 4종)은 v2의 "한국어 출력 강제 + 기존 카테고리 우선" 지시로 인해 사라졌다.

## 7. 결론 — 어느 모델을 채택할 것인가

### 7.1. 정량 비교 종합

| 평가 항목 | 우위 모델 |
|---|---|
| 4-class Core Accuracy | **8B 압승** (1.000 vs 0.821) |
| 클래스별 일관성 (선하증권 0% 회귀 유무) | **8B** (4B는 선하증권 인식 실패) |
| `기타` 거부 분기 (보수적 운영) | 4B-Instruct (분류 불가 30.8% vs 8B 0%) |
| 신규 카테고리 제안 일관성 | 동률 (둘 다 `품질증명서` 단일) |
| 출력 포맷 준수 | 동률 (둘 다 100%) |
| 응답 속도 | 4B (1.45× 빠름) |
| VRAM 점유 | 4B (−2.7GB) |

### 7.2. 결론

> **MVP 운영 모델로 Qwen3-8B를 채택한다.**

- 본 실험의 **결정적 격차는 4B-Instruct의 선하증권 0% 회귀**다. 6장 전부를 상업송장으로 오분류하는 것은 단순 정확도 하락이 아니라 **특정 카테고리 자체를 인식 못 하는 모드 실패**이며, 분류 엔진의 신뢰성을 근본적으로 훼손한다.
- v2 프롬프트가 v1에 있던 [Category Reference] (각 라벨의 한 줄 설명) 부분을 제거한 것이 4B의 라벨 의미 파악 능력을 결정적으로 약화시켰다. 8B는 자체 파라미터 지식으로 이를 보완할 수 있으나 4B는 그렇지 못하다.
- 메모리·속도 우위(2.7GB·1.45×)만으로 보상하기에는 정확도 격차(0.179)가 지나치게 크다. T4(16GB)·A100(40GB) 모두에서 8B Q4_K_M은 충분히 가동 가능하다.

### 7.3. 4B-Instruct를 살리려면

본 보고서 결과를 무용지물로 만들지 않으려면, 4B-Instruct는 다음 두 조건 중 하나가 성립할 때 재검토 가치가 있다.

1. **프롬프트 v2 보강**: [Category Reference] 한 줄 설명을 v2에 다시 추가한 v2.1 변종을 4B-Instruct로 재측정하여, 선하증권 회귀가 해소되는지 확인.
2. **도메인 파인튜닝**: 4B-Instruct 베이스에 물류 4-class 분류 LoRA를 학습해 8B 수준의 정확도를 달성할 수 있는지 검증. 성공 시 메모리·속도 우위가 활성화된다.

위 두 조건 모두 충족되지 않은 현 시점에서는 8B가 운영 모델로서 우월하다.
