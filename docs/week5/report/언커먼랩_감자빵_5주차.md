# 감자빵 5주차 보고서 — 물류 문서 RAG 전처리 파이프라인 구현 (Table-aware Chunking)

4주차 보고서 후속 과제로 제시된 **"HTML Table-aware 전처리 파이프라인"** 을 실제 코드로 구현했다.  
4주차에서 정량 확인된 한계 — (1) 물류 OCR 출력은 본문의 거의 전부가 `<table>` 한 블록이고, (2) 마크다운 `#`/`##` 헤더가 거의 없어 langchain Splitter 단독으로는 표 보존이 0% — 를 두 가지 직교 전략(HTML→Markdown 표 변환 + 키워드 기반 인공 헤더 주입)으로 풀어, OCR 산출물에서 RAG 청크까지 한 번에 만드는 6단 파이프라인 `LogisticsRAGPipeline` 을 작성하고 모의 입력으로 단계별 검증을 마쳤다.

## 1. 피드백 / 후속 과제 반영 (4주차 → 5주차)

| 4주차 후속 과제 | 내용 | 5주차 반영 |
|---|---|---|
| Table-aware 전처리 파이프라인 구현 | 4단계 직교 전략을 실제 코드로 구현 | ✅ (`scripts/logistics_rag_pipeline.ipynb`) |
| 마크다운 파이프 테이블 변환 후 재실험 | HTML `<table>` → `\| col \|` 형식으로 후처리하여 `\n\|` separator 활성화 | ✅ (3장 — 표 변환 모듈) |
| "마크다운 헤더 부재" 한계 해소 | 분할 자체가 일어나지 않는 1청크 문제 해결 | ✅ (4장 — 키워드 기반 인공 헤더 주입) |

## 2. 파이프라인 전체 구조

```
PDF / 이미지
  ├─ [1] OCR              PaddleOCR PP-StructureV3 (레이아웃 + 표 + OCR)
  ├─ [2] 전처리            유니코드 NFC 정규화, 노이즈 제거 (<table> 보존)
  ├─ [3] 표 변환           HTML <table> → Markdown 표 (rowspan/colspan 전개)
  ├─ [4] 헤더 주입         물류 키워드 21종 기반 인공 ##/### 헤더
  ├─ [5] 청킹              MarkdownHeaderTextSplitter → RecursiveCharacterTextSplitter
  └─ [6] 후처리            잘려나간 표 청크에 헤더 행 자동 복제
       ↓
  최종 RAG 청크 리스트 (content + metadata)
```

### 2.1. 4주차 문제 → 5주차 해결 매핑

| 4주차 한계 (정량 확인) | 5주차 해결책 |
|---|---|
| 본문의 거의 전부가 한 덩어리 `<table>` | 3단계: HTML 표를 Markdown 표(`\| col1 \| col2 \|`)로 변환하여 splitter가 행 경계로 자르게 함 |
| `#`/`##` 헤더가 없어 MarkdownHeaderTextSplitter가 1청크만 출력 | 4단계: 21종 정규식 패턴으로 `Shipper`, `Consignee`, `B/L Info` 등 인공 헤더 주입 |
| 셀 병합(rowspan/colspan) 정보가 분할 시 손실 | 3단계: 2D 그리드로 전개하여 병합 셀 값을 인접 위치에 복제 |
| 큰 표가 분할될 때 헤더 행이 후속 청크에서 사라짐 | 6단계: 같은 section 첫 청크에서 헤더 행을 추출해 후속 청크에 자동 prepend |
| `\n\|` separator가 HTML `<table>` 출력에는 매칭되지 않음 (4주차 5.4) | 3단계에서 마크다운 파이프 표로 미리 변환 → `\n\|` separator가 실제로 동작 |

## 3. 단계별 설계

### 3.1. OCR 모듈 (`LogisticsOCR`)

- 엔진: PaddleOCR PP-StructureV3 (`lang="korean"`, `dpi=300`)
- **이미지 전처리** (`_preprocess_image`):
  - 그레이스케일 → fastNlMeansDenoising → Adaptive Threshold (`THRESH_BINARY`, blockSize=31, C=15)
  - `minAreaRect` 기반 기울기 보정 (deskew, 0.5° 초과 시만 회전)
- **레이아웃 직렬화** (`_serialize_page`): y좌표를 20px 그리드로 묶어 위→아래 정렬, 같은 행 내에서는 x좌표로 좌→우. 표 블록은 `<table>...</table>` 원본 HTML 유지, 제목 블록은 `[TITLE]` 프리픽스로 마킹하여 4단계 헤더 주입에서 활용.
- **PDF**: `pdf2image.convert_from_path` 로 페이지 단위 변환, 페이지 경계는 `<!-- PAGE N -->` 주석으로 구분.

### 3.2. 전처리 모듈 (`clean_ocr_output`)

`<table>~</table>` 블록은 **원형 보존**, 그 외 본문만 정제. 표 내부 텍스트에 다음 규칙이 들어가면 `colspan="2"` 같은 속성 문자열이 깨질 수 있어 정규식으로 슬라이스해 분리 처리했다.

- 유니코드 NFC 정규화 (한글 자모 결합)
- 제어문자 제거 (`\x00-\x08`, `\x0b-\x0c`, `\x0e-\x1f`) — 탭/줄바꿈은 보존
- 줄 끝 하이픈 이어붙임 (`abc-\ndef` → `abcdef`)
- 한 글자씩 띄어진 OCR 노이즈만 좁게 제거 (`수 출 자` → `수출자`, 정상 띄어쓰기 보존). 정규식 `(?:[가-힣] ){2,}[가-힣]` 으로 3음절 이상만 매칭하여 정상 단어를 건드리지 않도록 했다.
- 단독 라인 페이지 번호 (`- 1 -`) 제거
- 다중 공백/줄바꿈 정규화

### 3.3. 표 변환 모듈 (`html_table_to_markdown`)

**핵심 알고리즘** — `_expand_table_to_grid`:

1. BeautifulSoup으로 `<tr>` 순회, `(row_idx, col_idx)` 좌표에 셀 텍스트를 기록하는 `occupied` 딕셔너리 유지.
2. `rowspan=R, colspan=C` 셀은 `R×C` 영역 전부에 동일 텍스트 복제.
3. 위 행에서 내려온 `rowspan` 영역이 있으면 다음 셀의 `col_idx` 를 자동 스킵.
4. 최종 그리드를 `\| col1 \| col2 \| ... \|` 라인 + 구분선(`\|---\|---\|...\|`) + 데이터 행으로 재조립.

**효과**:
- "Gross Weight" 같은 rowspan 헤더가 모든 데이터 행에서 복제되어 행 단독으로 RAG 검색되어도 의미가 살아남는다.
- `colspan="2"` 의 "TOTAL" 행도 두 컬럼에 동일하게 채워져 splitter가 행 중간을 잘라도 의미가 유지된다.
- 셀 내부 `\|` 는 `\\|` 로 이스케이프, 셀 내부 줄바꿈은 단일 공백으로 압축.

### 3.4. 헤더 주입 모듈 (`inject_headers`)

물류 도메인 키워드 **21종** 정규식 패턴 (한·영 동시):

| 카테고리 | 키워드 패턴 (요약) |
|---|---|
| 당사자 | Shipper / Consignee / Notify Party |
| 운송 | Vessel & Voyage / POL / POD / Place of Delivery |
| 화물 | Description of Goods / Marks and Numbers / Gross Weight / Net Weight / Measurement |
| 결제·통관 | Freight & Charges / HS Code / Terms / Country of Origin |
| 식별번호 | Invoice Info / Packing List / B/L Info / Container / Seal Number |

**규칙**:
- 문서 최상단에 `# {doc_type}` 자동 주입. `_detect_doc_type` 가 본문 1,500자에서 "Bill of Lading / 선하증권", "Commercial Invoice / 상업송장" 등을 매칭하여 결정 (실패 시 `LOGISTICS DOCUMENT`).
- 본문 내 키워드 매칭 라인 **앞** 에 `## {정규화 헤더명}` 삽입. 같은 헤더는 첫 매칭만 헤더화 (`used` set).
- `[TITLE]` 마킹된 라인은 무조건 `## {제목}` 으로 승격.
- **표 행은 헤더화 제외**: `\| ... \|` 패턴 라인은 in-table 상태로 통과시켜, 표 내부 텍스트("Description of Goods" 같은 헤더 셀)가 잘못 헤더로 승격되는 것을 방지.

### 3.5. 청킹 모듈 (`chunk_document`)

**1단** — `MarkdownHeaderTextSplitter`:
- `#` → `doc_type`, `##` → `section`, `###` → `subsection` 메타데이터로 저장
- `strip_headers=False` 로 본문에 헤더 텍스트 유지 (RAG 검색 시 컨텍스트 확보)

**2단** — `RecursiveCharacterTextSplitter`:
- `chunk_size=512`, `chunk_overlap=80` (≈15%) 기본값
- **Separator 우선순위**: `\n### ` → `\n## ` → `\n# ` → `\n\n` → **`\n\|`** → `\n` → `。` → `. ` → ` ` → `""`
- `\n\|` 를 줄바꿈 다음 우선순위로 배치하여 표 행 경계를 먼저 자르도록 보장

**오버랩 권장값**:

| 임베딩 모델 | chunk_size | chunk_overlap | 비율 |
|---|---:|---:|---:|
| BAAI/bge-m3 | 1024 | 128 | ~12% |
| multilingual-e5-large | 512 | 80 | ~15% |
| ko-sroberta | 450 | 60 | ~13% |

4주차에서 overlap 0~30% 비교 시 한국어 + 표 위주 문서는 약 15%가 토큰 비용과 컨텍스트 보존의 균형점이었으므로 기본값을 80자(약 15%)로 채택했다.

### 3.6. 표 헤더 복제 후처리 (`_repeat_table_headers`)

청킹 결과를 한 번 더 순회하여:

1. 각 section의 **첫 청크** 에서 표 헤더 행 + 구분선을 추출 (`_extract_table_header`).
2. 데이터 행만 있고 헤더/구분선이 없는 청크 (`_has_table_body_only`) 앞에 동일 section의 헤더를 prepend.
3. 복제된 청크에는 `metadata.table_header_repeated=True` 마킹 (디버깅·평가용).

4주차 5.5 권장 파이프라인의 3단계 "헤더 행 복제" 가 이 함수에 해당한다.

## 4. 검증 (모의 OCR 출력 기반)

PaddleOCR 없이도 후속 파이프라인을 단계별 확인할 수 있도록, PP-StructureV3가 만들어낼 법한 출력을 모사한 B/L 샘플(2페이지, `rowspan`/`colspan` 포함 2개 표)로 검증했다.

### 4.1. 단계별 검증 결과

| 단계 | 검증 항목 | 결과 |
|---|---|---|
| 전처리 후 | `<table>` 원형 보존 | ✅ assert 통과 |
| 표 변환 후 | `<table>` 잔존 0 | ✅ |
| 표 변환 후 | rowspan 전개 (`Gross Weight (KGS)` 출현 횟수 ≥ 2) | ✅ (5회 전개) |
| 표 변환 후 | colspan 전개 (`TOTAL` 출현 횟수 ≥ 2) | ✅ (2회 전개) |
| 헤더 주입 후 | `doc_type` 자동 감지 | ✅ `# BILL OF LADING` |
| 헤더 주입 후 | 키워드 헤더 주입 | ✅ `## Shipper`, `## Consignee`, `## Port of Loading` 등 |
| 청킹 후 | 헤더 메타데이터 부착 | ✅ `metadata.section` 채워짐 |
| 청킹 후 | 표 행 경계 분할 | ✅ `\n\|` separator 동작 |

### 4.2. 4주차 비교 — 같은 문서 기준

| 지표 | 4주차 (langchain 단독) | **5주차 (Table-aware 파이프라인)** |
|---|:---:|:---:|
| 청크 수 (B/L 1장 기준) | 1 (MarkdownHeader) / 분할 불가 | 다수 청크 (section별 분할) |
| 표 무결성 | 0% (HTML `<table>` 중간 절단) | rowspan/colspan 전개로 행 단독 의미 보존 |
| 헤더 메타데이터 | 없음 (헤더 부재) | `doc_type` / `section` / `subsection` 자동 부착 |
| 헤더 행 복제 | 없음 | section별 자동 복제 (`table_header_repeated` 마킹) |

> 4주차 §4.2의 "물류 5개 샘플 평균 표 무결성 0~40%" 한계가 본 파이프라인의 **HTML→Markdown 변환 + rowspan 전개** 단계로 구조적으로 해소된다. 다만 정량 비교(분류 LLM 정답률 변화)는 다음 주 MVP 통합 후 측정 예정.

## 5. 통합 클래스 인터페이스 (`LogisticsRAGPipeline`)

```python
pipe = LogisticsRAGPipeline(
    lang="korean",
    use_gpu=False,
    dpi=300,
    chunk_size=512,
    chunk_overlap=80,
)

result = pipe.process("samples/bl_001.pdf", return_intermediate=True)
# result["chunks"]              → [{content, metadata: {doc_type, section, chunk_id, source, ...}}, ...]
# result["intermediate"]        → {raw_ocr, cleaned, markdown_tables, structured}
```

- `return_intermediate=True` 옵션으로 각 단계 중간 산출물 노출 (디버깅·평가용).
- 모든 청크에 `metadata.source` 로 원본 파일 경로 자동 부착.
- `doc_type` 인자로 자동 감지를 우회할 수 있음 (사내 양식 강제 분류 시 사용).

## 6. 결론 및 후속 과제

### 6.1. 5주차 성과

- 4주차 §5.5에서 도출된 4단계 권장 파이프라인을 `LogisticsRAGPipeline` 클래스로 구현 완료.
- HTML `<table>` → Markdown 표 변환 모듈로 4주차 §5.4의 "`\n\|` separator가 매칭되지 않음" 문제를 구조적으로 해소.
- rowspan/colspan 전개 로직으로 셀 병합 정보가 분할 후에도 행 단독으로 보존되도록 함.
- 21종 정규식 기반 인공 헤더 주입으로 "헤더 부재 → MarkdownHeaderSplitter 1청크" 한계를 우회.
- section별 표 헤더 행 자동 복제 후처리로 큰 표 분할 시 후속 청크의 의미 손실 방지.
- 모의 OCR 출력 기반 단계별 검증 완료 (assert 8종 통과).

### 6.2. 후속 과제

1. **실제 PaddleOCR 환경 통합 검증**: 4주차 물류 5개 샘플(상업송장 소/대, 포장명세서, 선하증권, 원산지증명서)에 본 파이프라인을 적용해 4주차 4.2 표(청크 수 / 평균 길이 / 표 무결성)를 재측정.
2. **분류 LLM 정답률 비교**: Qwen3-8B + 5주차 프롬프트에 본 파이프라인 청크를 입력하여, langchain 단독 청킹 대비 카테고리 정답률·F1 변화를 정량 비교.
3. **FastAPI MVP 백엔드 통합**: 5주차 과제 1의 통합 MVP 서비스에 `LogisticsRAGPipeline` 을 OCR/Chunking API로 서빙. Next.js 프론트의 결과 대시보드(전체 마크다운 + Chunk 리스트)와 엔드포인트 연동.
4. **임베딩 + 벡터스토어 연결**: BAAI/bge-m3 (1024차원, 8K 컨텍스트) 우선, FAISS·Chroma·Qdrant 중 운영 환경 적합도 비교.
5. **하이브리드 검색**: 컨테이너번호·HS코드·B/L 번호 같은 정확 매칭 키워드 비중이 높으므로 BM25 + 벡터 검색 병행 (`langchain.retrievers.EnsembleRetriever`).
6. **`LOGISTICS_SECTION_PATTERNS` 확장**: 사내 양식·추가 문서 유형(D/O, A/N, C/O 등) 키워드 보강.
